# Playground


## ⚠️ This project is deliberately AI-generated

This project is, by design, almost entirely generated by AI. It exists as a personal
training ground for learning to work with AI coding tools. The architecture, code, tests
and documentation are overwhelmingly AI-authored, under human direction and review.

Treat it accordingly: an experiment first, a usable tool second.

---

The Scenet compiler running in a browser, published to GitHub Pages with the documentation.

**What it does, button by button, is in
[Use the playground](https://creatoan.github.io/scenet/howto/use_the_playground.html).** This
README is for building it.

The TypeScript here only moves strings across the boundary: the page runs the real compiler
under [Pyodide](https://pyodide.org/), which ships `shapely`, `geos`, `numpy`, `pydantic` and
`kiwisolver` compiled to WebAssembly, while `fontTools`, `pyyaml` and the font packages are pure
Python. Nothing is rebuilt or transformed for the browser; the guide's
[The compiler it runs](https://creatoan.github.io/scenet/howto/use_the_playground.html#the-compiler-it-runs)
says why that matters. The groups of the example menu, the opening example, the summaries and the
links all come from `examples/gallery/manifest.yaml`; `src/outline.ts` builds the Screen reader
tab and `src/maps.ts` the Output menu's layouts.

## Building

```bash
uv build --wheel        # from the repository root
cd playground
npm ci
npm run build           # writes dist/
```

`npm run assets` assembles what is not built from source into `public/` — Pyodide, the
wheels, the schemas, the gallery — and `vite build` writes the site, `public/` included,
to `dist/`. Serve `dist/` over HTTP — `file://` will not work, because Pyodide and
micropip both need real requests.

```bash
python -m http.server 8123 --directory dist
```

## Pinned dependencies, and why

**`monaco-editor` is pinned to exactly 0.54.0.** Version 0.55 replaced its wildcard
exports map, so `monaco-editor/esm/vs/...` no longer resolves, and 0.56 changed the worker
`initialize` contract. `monaco-worker-manager` — a transitive dependency of `monaco-yaml`
— still uses the old path and the old contract, so on 0.55 or later the YAML worker never
registers a handler.

The two breaks fail differently. The exports map is loud: the worker imports stop
resolving and the build fails. CI builds the playground for exactly that reason — 0.57
was merged while every check passed, and only the Pages deploy noticed. The `initialize`
contract is quiet: the page loads and the editor appears, but schema validation,
completion and hover are gone, and the console fills with
`Missing requestHandler or method: doValidation` on every keystroke. No check catches
that one, so before merging a monaco-editor update, open the playground and type a key
the schema does not allow.

`monaco-yaml` declares `monaco-editor: >=0.36`, a range written before any of this. The
fix has to come from `monaco-yaml` shipping an updated worker manager, so that is the
dependency to watch. Dependabot is told to ignore monaco-editor 0.55.x, 0.56.x and 0.57.x
specifically — 0.58 and later will still be proposed.

**`dompurify` is overridden forward to ^3.4.16.** monaco-editor 0.54.0 pins 3.1.7 exactly,
and even 0.57.0 pins 3.4.15; advisories affect everything up to 3.4.15. npm's own
`audit fix --force` suggests *downgrading* monaco to 0.53 instead, which fixes nothing.

Dependabot cannot move the override either. Its security update for dompurify fails as
`update_not_possible`, because the only path it finds downgrades monaco-editor, so a new
DOMPurify advisory means raising the floor here by hand, the lockfile with it.
